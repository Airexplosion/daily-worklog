# 《每日工作总结生成器》开发需求文档

> 交付对象：Windows 桌面端开发（人或 AI 编码助手均可直接按本文档实现）
> 需求方：张三（新媒体运营岗）
> 文档版本：v1.0

---

## 0. 一句话说清这是什么

一个常驻 Windows 托盘的桌面小软件：白天每做完一件事，按一个热键框选屏幕截图，顺手补一句话，AI 把「截图内容 + 你补的话」变成一条工作条目；到设定时间弹窗提醒下班并自动生成一份**严格套用固定格式**的《张三MM.DD 工作梳理》；支持按日期区间导出，作为做 PPT 的素材库。

**核心指标：记录一个动作 ≤ 5 秒，生成总结 ≤ 10 秒。**

---

## 1. 使用者与场景

- 使用者：张三，一个人用，单机，不需要账号、不需要云同步。
- 工作特征：一天做的事很碎——收入确认填写、合声计划 PPT 修改、百应提现与计算、团播头像/背景更换、直播间使用状况反馈与跨部门协调等。下班前靠回忆写总结要花 20 分钟，还容易漏。
- 真实痛点：**很多工作内容不在截图上**。比如"沟通王老师关于 21 楼直播间锁坏了的事儿"，屏幕上只有个聊天窗口，AI 看截图永远推不出"王老师"和"21 楼"。所以「人工补一句话」不是可选项，是核心环节。

---

## 2. 硬性格式要求（最高优先级，不可自由发挥）

生成的总结必须**逐字**符合下面这个样式：

```
张三10.15工作梳理
1.拼多多收入确认填写
2.合声计划县域ppt修改
3.百应提现，计算。
4.继续更换团播头像/背景头图
5.共享直播间使用状况反馈，沟通王老师关于21楼直播间锁坏了的事儿。
```

格式规则（开发时逐条落实）：

| 项 | 规则 |
|---|---|
| 标题 | `张三` + `MM.DD` + `工作梳理`，如 `张三10.15工作梳理`。月日之间用英文句点，**不补零**（10.15、11.3） |
| 条目 | 一行一条，`1.` `2.` `3.` 连续编号，**编号后不留空格** |
| 长度 | 每条 8–30 字，一件事一行，不分点不换行 |
| 句式 | 动宾结构、口语化，允许"继续""沟通"这类词，允许逗号连接两件事 |
| 禁用词 | "完成""今天""共计""顺利""进一步""持续""有效推进"等书面套话 |
| 句末 | 句号可有可无，不强制统一（照原样保留用户习惯即可） |
| 条数 | 等于实际条目数，**不许为了好看凑到 5 条** |
| 禁止 | 不得新增未记录的日期、人名、数字、项目名；不得写总结语、点评、前言 |
| 输出 | 纯文本，**不带任何 Markdown 标记**（不能出现 `#` `*` `-` ），粘到微信和 Word 里必须干净 |

## 3. 功能清单

### P0（不做完不算交付）

1. 全局热键触发截图（可自定义，默认 `Ctrl+Alt+S`）
2. 屏幕区域框选，支持多显示器、支持 Windows 125%/150% 缩放
3. 截图后立即弹出「一句补充说明」输入浮层（可由输入法语音输入）
4. AI 识图 → 生成一条工作条目（OpenAI 兼容接口，多模态）
5. 条目可编辑、可删除、可手动补录
6. 当日工作清单视图
7. 定时弹窗提醒（可设时间，可选仅工作日，含漏提醒补偿）
8. 一键生成总结 + 一键复制到剪贴板
9. 本地数据存储 + 设置页
10. 开机自启、托盘常驻、单实例运行

### P1（第一版跑通后补）

11. 日期区间导出（Markdown / Excel / Word 三种）
12. 同类条目自动合并去重
13. 多张截图合并为同一条目
14. 数据备份与导入
15. 原始截图留痕（可回看当天那张图）

## 4. 模块详细要求

### 4.1 截图

- 全局热键唤起，主窗口可在前台也可在后台（最小化到托盘时同样响应）。
- 唤起后**所有显示器同时进入框选模式**（半透明遮罩 + 十字光标 + 实时显示选区像素尺寸）。
- 鼠标拖拽框选，松开即完成；按 `ESC` 取消整个操作。
- 必须正确处理 Windows 显示缩放：150% 缩放下裁剪出来的图不能偏移、不能压缩变形、不能只截到半个屏。
- 截到的图存为 PNG，落到本地 `shots/` 目录，文件名用时间戳 ID。
- 截图完成后立刻进入「补充说明」浮层，不要先跳主窗口。

### 4.2 补充说明浮层（核心，不能砍）

- 浮层出现在屏幕中下部，显示截图缩略图 + 一个单行输入框，**焦点默认在输入框内**，用户可以直接用输入法（含语音输入）说话。
- 占位提示文案：`一句话说清这是在干啥（可直接语音输入）`
- 回车 = 提交；`ESC` 或点"跳过" = 只用截图生成。
- 这一栏要有明显的视觉引导，比如"截图里没有的信息（人名、地点、原因）请补在这里"。

### 4.3 AI 识图

- 接口：**OpenAI 兼容的 `POST {baseURL}/chat/completions`**，支持自定义 `baseURL` / `apiKey` / `model` 三个字段，不绑定任何一家服务商（通义千问、豆包、DeepSeek、Kimi、智谱、OpenAI 均可）。
- 图片以 `image_url` 形式传 base64 data URL（`data:image/png;base64,...`），不要依赖外链上传。
- 一次请求只处理一张图 + 一段补充文字，输出**严格 JSON**，不许多余字符。
- 要求 JSON 字段：`{"item": "一条工作条目", "project": "归类", "confidence": 0.0-1.0}`，其中 `project` 枚举：`拼多多 / 百应 / 合声计划 / 团播 / 直播间 / 绩效 / 其他`。
- `confidence < 0.5` 时，条目仍然入列，但标黄提示"AI 没太看懂，建议改一下"。
- 超时 20 秒；失败重试 1 次；仍失败则**不能丢数据**——回退为"截图已保存，请手动填写这一条"。
- 设置页提供开关：`□ 截图内容发送给 AI 服务商`。关掉后只用手动文字生成，不上传任何图片（隐私敏感场景用）。

**识图用的系统提示词（原样写进代码）：**

```
你是张三的工作记录整理助手。用户会给你一张电脑屏幕截图，以及（可能有）用户手写的一句话补充说明。

任务：输出一条符合张三工作梳理格式的工作事项。

规则：
1. 只输出一条，8-30字，动宾结构，口语化，不要书面美化。
2. 描述"做过的一件事"，不是"打开了某个软件""看到了某个页面"。
3. 用户补充说明的优先级高于截图内容；两者冲突时以补充说明为准。
4. 严禁编造截图和补充说明里都不存在的信息（人名、数字、项目名、地点、时间）。
5. 不要出现"完成""今天""共计""顺利""进一步""持续"等词。
6. 不加编号，不换行，句末不加句号。
7. 如果截图是财务报表或表格，提炼"在做什么业务动作"（如：收入确认填写、提现金额核算、对账），不要罗列数字。
8. 如果实在判断不出在做什么，item 输出"（待补充）"，不要瞎猜。

只输出 JSON，不要任何其他文字：
{"item":"...","project":"拼多多|百应|合声计划|团播|直播间|绩效|其他","confidence":0.0}
```

### 4.4 条目管理

- 当日清单按**记录顺序**从上到下排列（与最终成文编号一致），最新记录追加在末尾。
- 双击条目文字直接原地编辑，失焦自动保存。
- 删除不做二次确认弹窗，改为删除后 Toast 提示「已删除 · 撤销」，5 秒内可撤回。
- 每条左侧显示来源小标签：`AI` 或 `手动`；有截图的显示缩略图角标，点击可看大图。
- 支持手动「+ 添加一条」，用于忘截图的情况。
- 支持把两条拖到一起合并（P1 可延后）。

### 4.5 定时提醒

- 默认时间 `18:00`，设置页可改（选时分）。
- 可选 `仅工作日提醒（周一至周五）`，默认开启。
- 触发时：弹出主窗口到前台 + 系统通知，文案——
  **标题：**`该下班了`
  **正文：**`今天的工作总结可以生成了，已记录 N 条`
- **漏提醒补偿（必须有）**：如果到点时电脑处于休眠/关机状态，则下次启动软件时，若当日尚未生成总结，立即补弹一次。
- 生成完成后当日不再重复提醒。
- 提供「今天不再提醒」按钮。

### 4.6 生成总结

- 点「生成今日总结」→ 3 秒内出结果，用打字机效果流式显示，让用户感觉在干活。
- 生成时把**当日全部条目**（含手动补录、含已编辑内容）作为输入，让模型去重合并、轻微润色，但**绝不允许新增信息**。
- 出结果后可继续编辑，然后「复制」或「保存归档」。
- 复制进剪贴板的内容必须是纯文本，粘到微信/企业微信/Word 后无任何符号残留。

**汇总用的系统提示词（原样写进代码）：**

```
你是张三的助手，把当天记录的若干条工作事项整理成一份工作梳理。

输出格式严格为：第一行标题，第二行起为编号条目。
张三10.15工作梳理
1.xxx
2.xxx

规则：
- 标题固定为 "张三" + 月.日 + "工作梳理"，日期用 MM.DD 格式不补零（如 10.15、11.3）。
- 每条一行，编号从 1 开始连续，编号后不加空格。
- 保留原条目的大意和口语感；表述同一件事的重复条目要合并成一条。
- 严禁新增任何原始条目中未出现的信息（人物、数字、地点、原因）。
- 条数等于合并后的实际条数，不许凑数。
- 不要输出解释、前言、总结、点评。
- 输出纯文本，禁止使用 Markdown 标记（# * - 等）。
```

### 4.7 区间导出（做 PPT 用）

- 顶部提供起止日期选择，默认本月 1 日至今。
- 三种导出：
  - **Markdown（.md）**：每天一个标题块，原样格式，方便直接看。
  - **Excel（.csv，UTF-8 带 BOM 保证 Excel 打开不乱码）**：列 = `日期 / 序号 / 工作条目 / 归类 / 来源`，一行一条，方便做数据透视。
  - **Word（.docx）**：日期分组的条目列表，可直接当汇报底稿。
- 额外提供「按项目归类」统计视图：某段时间内各项目被提到多少次、分别是哪几天，供 PPT 排章节用。

### 4.8 存储

- 路径：`%APPDATA%/DailyWorkLog/`
- `data.json`：按日期键存储，格式 `{ "2026-10-15": { "items": [...], "summary": "...", "generatedAt": "..." } }`
- `settings.json`：`baseURL` / `apiKey` / `model` / `hotkey` / `remindTime` / `weekdayOnly` / `autoStart` / `sendImageToAI` / `userName`
- `shots/`：原始 PNG
- 每次启动时把 `data.json` 复制为 `data.bak.json`（只留最近一份即可）
- API Key 明文存储在本地即可，但设置页显示时用 `sk-****abcd` 掩码。

### 4.9 系统集成

- 开机自启（写入注册表 Run 项或启动文件夹）
- 托盘图标常驻，右键菜单：`截一张` / `打开主窗口` / `生成今日总结` / `退出`
- 单实例锁：重复启动只唤起已有窗口，不新开进程
- 点关闭按钮 = 最小化到托盘，首次需 Toast 提示「已最小化到托盘，不会退出」
- 热键注册失败（被别的软件占用）要明确提示，并引导去设置页换一个

## 5. 界面

- 单窗口，一屏搞定：顶部一行显示 `2026年10月15日 周四 · 今日已记录 5 条`；中间是条目清单卡片；底部一个大的主按钮「生成今日总结」。
- 右下角固定一个圆形悬浮按钮「截一张」，与热键等效。
- 左侧三个标签页：`今日` / `历史` / `设置`。
- 风格：干净的浅色卡片式，圆角、留白充足，不要花哨渐变和动效噪音。字体用系统中文字体（微软雅黑 / 思源黑体）。

## 6. 异常与边界

| 情况 | 处理 |
|---|---|
| 没配 API Key 就截图 | 不报错，提示"先去设置页填接口信息，或手动写这一条"，截图先存下 |
| AI 返回的不是合法 JSON | 正则抢救提取 `item` 字段；救不出来就退回原始文字让用户手改 |
| 网络断了 | 条目进"待处理"队列，恢复后不自动重试（避免偷跑额度），给个手动重试按钮 |
| 跨零点还在加班 | 条目归属以截图发生时的时间戳为准，不做跨天合并 |
| 当天 0 条就想生成 | 允许，生成空标题 + 提示"今天还没记录" |
| 软件崩溃 | 条目一旦确认入列就立刻落盘，不允许只在内存里 |
| 多屏 + 不同缩放比 | 每个屏按自己的 scaleFactor 单独换算，不许统一按主屏算 |

## 7. 验收清单（照着逐条测，全过才算完）

1. 按 `Ctrl+Alt+S`，在 150% 缩放的主屏上框选一小块区域，出来的图和框选范围**完全一致**，无偏移无变形。
2. 双屏环境下在副屏框选，同样正确。
3. 框选后立刻能打字，中文输入法正常，回车后条目出现在今日清单里。
4. 补一句"沟通王老师21楼直播间锁坏了"，生成的条目里**必须出现"王老师"和"21楼"**（这是检验 AI 是否用了补充说明的关键用例）。
5. 生成出来的文本，粘到微信输入框，**不出现任何 `#` `*` `-`**。
6. 标题日期是 `张三10.15工作梳理` 这种格式，不是 `2026-10-15` 也不是 `10月15日`。
7. 条目编号从 `1.` 开始连续，编号后面没有空格。
8. 手动加一条、改一条、删一条（能撤销），刷新界面后数据还在。
9. 把系统时间改到 18:00，能收到弹窗 + 系统通知；改到周末且开着"仅工作日"，不提醒。
10. 关机跨过 18:00，再开机启动软件，能补弹一次提醒。
11. 重启电脑后软件自动启动，托盘有图标，双击能开窗口。
12. 再双击一次 exe，不会出现第二个进程。
13. 导出上个月的 CSV，用 Excel 打开中文不乱码，一行一条。
14. 断网状态下截图，软件不崩，条目能手动保存。

## 8. 技术建议

- **Electron + 原生 HTML/CSS/JS**，不引 React/Vue（依赖越少越不容易烂）。
- 截屏用 `desktopCapturer` 抓屏 + 自建透明浮层做框选，**不要用第三方截屏库**（在 Windows 高 DPI 下普遍有坑）。
- 数据用 JSON 文件即可，**不要上数据库**（数据量小，且方便用户自己备份）。
- 打包用 `electron-builder` 出 NSIS 安装包，打包时配置国内镜像，否则二进制下载会卡。
- 托盘和窗口图标需要自己准备 `.ico` / `.png`（32×32 与 256×256 两套）。

---

## 9. 明确不要做的

- ❌ 云同步、账号登录、多端（就一台电脑一个人）
- ❌ 移动端
- ❌ 图表报表、思维导图、KPI 分析
- ❌ 把总结格式做成"可配置模板"（固定成张三的格式，简单优先）
- ❌ "让 AI 帮你润色得更有汇报感"——**禁止美化**，用户要的就是平实罗列
- ❌ 自动给条目打分、评估工作饱和度这类功能

---

## 10. 交付顺序建议

先打通这一条最小闭环，别一上来做导出和统计：

> 热键截图 → 补一句话 → AI 出条目 → 手动改 → 定时提醒 → 一键成文 → 本地存

这条闭环在真人手里跑 3 天没问题了，再补区间导出、归类统计、多图合并。
