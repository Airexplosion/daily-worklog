## 0. 一句话说清这是什么

一个常驻 Windows 托盘的桌面小软件：白天每做完一件事，按一个热键框选屏幕截图，顺手补一句话，AI 把「截图内容 + 你补的话」变成一条带标签的工作条目；到设定时间提醒下班并生成一份**严格套用固定格式**的《{姓名}{月.日}工作梳理》。

**核心指标：记录一个动作 ≤ 5 秒（从按热键到补充框消失），生成总结 ≤ 10 秒（首字 ≤ 3 秒）。**

## 1. 使用者与场景 【改】

- 最初的使用者是张三（新媒体运营岗）。**这个软件会发给同事用**，每个人装在自己电脑上，单机使用。
- 不做账号、不做云同步、不做多端。
- **每个人用自己申请的 API Key**，第一次启动时由引导页带着填好。
- 工作特征和真实痛点同 v1.0：一天的事很碎，很多信息不在截图上（比如"王老师""21 楼"），所以"人工补一句话"是核心环节，不能砍。

## 2. 目标 / 非目标 / 反目标

**目标**

1. 记录一条 ≤ 5 秒，记完就能接着干活，不用等 AI。
2. 生成的总结格式逐字正确，复制粘到微信、企业微信、Word 里干干净净。
3. 同事拿到安装包，不需要管理员权限，2 分钟内装好、填好、截出第一张。
4. 轻：安装包 ≤ 15MB，托盘常驻时尽量少占内存。
5. 好看：Win11 原生风格（见第 8 节），看起来像正规软件。

**非目标**（这一版不做）

- 云同步、账号、移动端、多端（同 v1.0）
- 图表报表、思维导图、KPI 分析、工作饱和度打分（同 v1.0）
- **区间导出（Markdown / CSV / Word）和按项目统计视图：暂缓**，主流程跑通后再单独讨论【改】
- 深色模式【我的判断】
- 代码签名证书（第一版不买）【我的判断】
- 软件内自动下载安装新版本（只提示、引导到 GitHub 下载）

**反目标**（技术上能跑，但出现这些就算失败）

- AI 编造截图和补充说明里都没有的人名、数字、地点、项目名
- AI 把总结"润色得更有汇报感"
- 任何情况下丢掉一条已经确认的记录（AI 失败、断网、崩溃、断电）
- 复制出来的总结里出现 `#` `*`、行首 `-`、编号后的空格、补零日期
- 打扰用户：强制更新、多余的确认弹窗、截图时弹更新提示
- 同事装不上、被杀毒软件拦了却没人告诉他怎么办

## 5. 硬性格式要求（最高优先级） 【改】

示例（以张三为例）：

```
张三10.15工作梳理
1.拼多多收入确认填写
2.合声计划县域ppt修改
3.百应提现，计算。
4.继续更换团播头像/背景头图
5.共享直播间使用状况反馈，沟通王老师关于21楼直播间锁坏了的事儿。
```

| 项 | 规则 | 谁来保证 |
|---|---|---|
| 标题 | `{姓名}` + `{月}.{日}` + `{标题后半句}`。后半句默认"工作梳理"，引导页可改。日期不补零（10.15、11.3）。**标题由代码拼，不让 AI 写**【改】 | 代码强制 |
| 编号 | `1.` `2.` 连续编号，编号后不留空格 | 代码强制（重新编号） |
| 符号 | 纯文本，不出现 `#` `*`，行首不出现 `-` `•` `>` | 代码强制（清洗） |
| 空行 | 不允许 | 代码强制 |
| 换行符 | 复制到剪贴板时用 `\r\n` | 代码强制 |
| 长度 | 每条**建议** 8–30 字。v1.0 的示例里第 3 条不到 8 字、第 5 条 33 字，所以只做提醒，不强制，也不自动截断【改】 | 只提醒 |
| 句式 | 动宾结构、口语化，允许"继续""沟通"，允许逗号连接两件事 | 提示词约束 |
| 禁用词 | 合并成一份可配置的列表，默认：完成、今天、共计、顺利、进一步、持续、有效推进【改】 | 提示词约束 + 出现时提醒（不自动删） |
| 句末句号 | AI 识图生成的单条不带句号；手动写的、手动改过的保留原样；总结里的每一行，模型输出什么结尾就保留什么，代码不管，用户想改可以直接改【改：统一了 v1.0 里两处说法】 | 提示词 + 代码去掉 AI 单条末尾的"。" |
| 条数 | 等于合并后的实际条数，不许凑数 | 提示词约束 + 提醒（条数比记录多时提醒） |
| 不新增信息 | 不得新增未记录的日期、人名、数字、项目名；不写总结语、点评、前言 | 提示词约束 + 代码检测"原始记录里没有的数字和英文词"并提醒 |

**所有人统一、不开放修改的**【我的判断】：编号格式、日期不补零、纯文本、不新增信息。同事能改的只有：姓名、标题后半句、标签、口吻范例、禁用词，以及高级设置里的完整提示词。

## 7. 模块详细要求

### 7.1 截图 【改】

界面稿：`4-截一张流程.html` ①

- 全局热键唤起，主窗口在前台、后台或最小化到托盘时都响应。如果截图流程已经在进行中，再按热键无效。
- **先冻结，再框选**：按下热键的瞬间，用 Rust 把每块显示器的整屏画面抓进内存（按物理像素）。然后每块显示器各显示一个全屏的框选窗口，背景就是这块屏刚抓到的画面，上面盖一层半透明遮罩。框选窗口不需要透明，因为背景已经是定格画面。
- 每块显示器一个框选窗口，按这块屏自己的物理范围摆放。**不许**做一个跨所有屏幕的大窗口。
- 框选只能在一块屏内进行，不支持跨屏框一个区域【我的判断】。
- 十字准线；选区上方实时显示物理像素尺寸，比如 `1280 × 540`；屏幕顶部居中一行提示："拖动鼠标框选　Esc 取消　右键 重选"。右键重选是新增的【我的判断】。
- 松开鼠标即完成。Esc 取消整个操作，所有框选窗口一起关掉。
- **坐标换算**：选区在网页里是 CSS 像素，乘以这块屏的缩放比例，换算成这块屏图片上的物理像素，然后**从内存里的原始整屏图裁剪**，不从网页里显示的图裁。150% 缩放下，裁出来的图和框选范围必须一模一样，不能偏移、变形，也不能只截到半个屏。
- 速度：从按下热键到框选画面出现 ≤ 0.5 秒（目标）。框选窗口在软件启动时就提前建好并隐藏，用的时候直接显示【我的判断】。定格画面怎么传给网页（临时文件、自定义协议或其他方式）由开发者决定。
- 存盘：裁好的原图存成 PNG，放在 `shots/` 目录，文件名用条目 ID。
- 截图完成后直接进入补充框，不打开主窗口。

### 7.2 补充说明浮层（核心，不能砍）

界面稿：`4-截一张流程.html` ②

- 小窗口出现在**截图那块屏**的中下部，背景轻微变暗。左边是截图缩略图，右边是标题"这一条在干啥？"和一个单行输入框。**焦点默认在输入框里**，可以直接打字。
- 占位文字：`一句话说清这是在干啥（可直接语音输入）`
- 输入框下方有一行黄色提示：`截图里没有的信息（人名、地点、原因）请补在这里`
- 语音输入：输入法自带的语音和 Windows 自带的 Win+H 都能用，不需要做额外开发，验收时确认一下【新】。
- 回车 = 记录；Esc 或点"跳过" = 只用截图生成。
- 左下角放一个"＋ 再截一张，合到这条"的入口，属于 P1。P0 阶段可以不显示，也可以显示成不可点的灰色【我的判断】。

### 7.3 后台识别与"记好了"提示 【新】

界面稿：`4-截一张流程.html` ③

- 按回车后，补充框**立刻**关闭（≤ 0.3 秒），同时条目**立刻落盘**，状态为"识别中"，AI 在后台识别。用户不需要等 AI。
- 屏幕右下角弹出一个小提示窗（软件自己画，不用系统通知）：`已记录第 N 条 · AI 识别中…`，下面显示用户补的那句话。
- 识别完成后，提示变成：`✓ 第 N 条已生成` + 条目文字 + 标签 + "改一下"按钮。点"改一下"打开主窗口，并让这条进入编辑状态。
- 约 5 秒没动作，提示自动消失；鼠标悬停时不消失【我的判断】。
- 失败时（AI 报错、超时、断网、没配 Key），提示改为：`截图已保存，有空手动写一句`。条目留在清单里，状态为"待处理"。
- 连续快速截好几张时，按顺序排队识别，每一条都独立落盘。

### 7.4 AI 接口 【改】

- 协议：OpenAI 兼容的 `POST {baseURL}/chat/completions`，不绑定任何一家服务商。
- **两套模型配置**【改】：
  - **识图模型**：必须能看图，用来逐条生成条目。
  - **汇总模型**：只处理文字，用来生成总结，可以用便宜的模型。
  - 两套默认共用同一个 baseURL 和 Key，高级设置里可以分开填。
- **服务商预设**：选好服务商就自动填 baseURL 和默认模型名。模型名在实现时以各家官网为准；下面的只是参考：

  | 服务商 | baseURL | 识图 | 汇总 |
  |---|---|---|---|
  | 通义千问（默认推荐） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | qwen-vl 系列 | qwen-plus 等 |
  | 豆包（火山方舟） | `https://ark.cn-beijing.volces.com/api/v3` | 视觉模型 / 接入点 ID | 文本模型 |
  | 智谱 | `https://open.bigmodel.cn/api/paas/v4` | glm-v 系列 | glm 系列 |
  | Kimi | `https://api.moonshot.cn/v1` | vision 系列 | kimi / moonshot 系列 |
  | DeepSeek | `https://api.deepseek.com` | （不能识图，只能当汇总模型） | deepseek-chat |
  | 自定义 | 手填 | 手填 | 手填 |

- 每个预设配一个"怎么申请 Key"的教程链接，打开的是服务商的官方页面【我的判断】。
- 图片：发送前缩放到长边不超过 1600 像素，编码成 JPEG（质量约 85），以 `data:image/jpeg;base64,...` 的 `image_url` 形式发送。本地存档的仍然是 PNG 原图【改】。
- 一次识图请求只处理一张图加一段补充文字。
- **识图返回格式**【改：从单个 `project` 改成多个 `tags`】：

  ```json
  {"item":"一条工作条目","tags":["标签1","标签2"],"confidence":0.0}
  ```

  - `tags` 有 1–3 个。现有标签里没有的，就是 AI 新建的标签（见 7.6）。
  - `confidence < 0.5` 时，条目照样入列，但标黄提示"AI 没太看懂，建议改一下"。
- **解析容错**：
  1. 去掉 `<think>…</think>` 思考段，忽略返回里的 `reasoning_content` 字段
  2. 去掉 ```json 代码块标记
  3. 按 JSON 解析
  4. 解析失败时，用正则抢救 `item` 和 `tags`
  5. 还是救不出来，就把模型返回的原始文字放进条目，标黄，让用户手改
- 不依赖 `response_format: json_object`，因为不是每家都支持【我的判断】。
- 超时 20 秒，失败重试 1 次；仍然失败就转为"待处理"，数据不丢。
- 断网：条目进"待处理"状态，网络恢复后**不自动重试**（避免偷偷消耗额度），条目上提供"重试"按钮，清单顶部提供"全部重试"。
- **截图内容发送给 AI** 开关（设置页，默认开）：关掉后只发补充文字，用纯文字版提示词生成条目。没写补充文字的条目直接进"待处理"，等用户手写。任何情况下都不上传图片。
- 生成总结用流式输出（`stream: true`），实现打字机效果。如果服务商不支持流式，就一次性显示结果。

### 7.5 提示词 【改】

- 两段提示词都改成**模板**。变量由程序填入，同事不用碰原文。
- 同事在引导页和设置页里改的是"填空"：姓名、标签、口吻范例、禁用词。
- **高级：直接改完整提示词**。打开后看到的是模板原文，可以随意改，旁边有"恢复默认"按钮。
- 无论提示词怎么改，"只输出 JSON……"这段**固定结尾由代码在发送前自动追加**，界面上看不到，也改不了；总结的格式由第 5 节的代码清洗兜底。

**识图提示词模板（原样写进代码）：**

```
你是{姓名}的工作记录整理助手。用户会给你一张电脑屏幕截图，以及（可能有）用户手写的一句话补充说明。

任务：输出一条符合{姓名}工作梳理格式的工作事项，并打上标签。

规则：
1. 只输出一条，8-30字，动宾结构，口语化，不要书面美化。
2. 描述"做过的一件事"，不是"打开了某个软件""看到了某个页面"。
3. 用户补充说明的优先级高于截图内容；两者冲突时以补充说明为准。
4. 严禁编造截图和补充说明里都不存在的信息（人名、数字、项目名、地点、时间）。
5. 不要出现这些词：{禁用词，用顿号连接}。
6. 不加编号，不换行，句末不加句号。
7. 如果截图是财务报表或表格，提炼"在做什么业务动作"（如：收入确认填写、提现金额核算、对账），不要罗列数字。
8. 如果实在判断不出在做什么，item 输出"（待补充）"，不要瞎猜。
9. 标签 1-3 个，优先从现有标签里选：{现有标签，用顿号连接；没有则写"（暂无）"}。{新建标签规则}
{口吻范例段}
```

- `{新建标签规则}`：
  - 开关打开时：`现有标签都不合适时，可以新起一个 2-6 字的短标签。`
  - 开关关闭时：`只能从现有标签里选；都不合适就用"其他"。`
- `{口吻范例段}`：用户贴过范例时，内容为 `以下是{姓名}以前写过的总结，学习其口吻和用词，不要照抄内容：\n{范例}`；没贴就为空。
- 纯文字版（关掉"发送截图"时用）：把第一段改成"用户会给你一句话说明"，去掉第 7 条，其余相同。

**固定结尾（代码追加，不可改）：**

```
只输出 JSON，不要任何其他文字：
{"item":"...","tags":["..."],"confidence":0.0}
```

**汇总提示词模板（原样写进代码）：**

```
你是{姓名}的助手，把当天记录的若干条工作事项整理成一份工作梳理。

只输出编号条目，不要输出标题：
1.xxx
2.xxx

规则：
- 每条一行，编号从 1 开始连续，编号后不加空格。
- 保留原条目的大意和口语感；表述同一件事的重复条目要合并成一条。
- 严禁新增任何原始条目中未出现的信息（人物、数字、地点、原因）。
- 条数等于合并后的实际条数，不许凑数。
- 不要出现这些词：{禁用词}。
- 不要输出解释、前言、总结、点评。
- 输出纯文本，禁止使用 Markdown 标记（# * - 等）。
{口吻范例段}
```

- 给汇总模型的输入：当天所有"已完成"状态的条目，按记录顺序排好，每行一条，只给文字，不给标签。"待处理"状态的条目不参与汇总，生成前提示"还有 N 条待处理，没算进去"【我的判断】。

### 7.8 生成总结 【改】

界面稿：`5-生成总结与历史.html` ①

- 点"生成今日总结"后，今日页切换到总结视图，文字用打字机效果流式显示。
- **代码处理流程**（只对模型刚生成的结果执行一次）：
  1. 去掉思考段、代码块标记
  2. 按行拆开，去掉首尾空白，删掉空行
  3. 第一条编号行之前的内容（模型自作主张写的标题、前言）和最后一条之后的内容（总结语）都删掉。删掉了什么，就在检查栏里提示"已去掉 AI 多写的：……"
  4. 删掉所有 `#` `*` 和反引号，删掉行首的 `-` `•` `>`
  5. 去掉旧编号（支持 `1.` `1、` `1．` `1)` 后面带不带空格），重新编成 `1.` `2.` ……
  6. 在最前面加上代码拼好的标题
- **检查栏**（只提醒，不改内容）：
  - 全部通过时显示绿色："编号连续 · 无多余符号 · 没有新增人名数字"
  - 有问题时逐条黄色提示：某条超过 30 字或不到 8 字、出现禁用词、出现原始记录里没有的数字或英文词、条数比记录还多
- 总结区域可以直接编辑。编辑完自动保存，但不会再触发重新编号，用户怎么改就怎么存【我的判断】。
- **复制时**只做两件事：删掉 `#` `*` 反引号和行首的 `-` `•` `>`，把换行统一成 `\r\n`。不重新编号，不删行，也不重建标题。历史页复制旧总结时，标题保持当时生成的样子，即使后来改了名字也不变【我的判断】。
- **不设单独的"保存归档"按钮**：生成后自动存档，编辑后自动保存。主按钮只有一个："复制到剪贴板"，复制的是纯文本，换行用 `\r\n`【改】。
- "重新生成"：不弹确认框，直接覆盖；右下角出现"已重新生成 · 撤销"，可以回到上一版，包括手改过的版本【我的判断】。
- 总结过期：生成之后又增、删、改了条目，今日页底部的按钮变成"记录有改动 · 重新生成"。
- 当天 0 条：允许生成，只输出标题，并提示"今天还没记录"。
- 生成完成后，当天不再提醒。

### 7.9 定时提醒 【改】

- 默认 `18:00`，设置页可改。
- "只在工作日提醒"默认开启。**工作日的判断用法定节假日数据**：
  - 放假的周一到周五不提醒
  - 调休上班的周六、周日照常提醒
  - 打包进来的数据没有当前年份时，退回"周一到周五"的规则，并在设置页提示"节假日数据过期，请更新软件"
- 实现方式：Rust 每 30 秒检查一次当前时间，不用一次性的定时器。这样改系统时间、电脑睡眠后唤醒都能正确触发，不需要单独处理唤醒事件【改】。
- 触发条件（全部满足才触发）：
  - 今天是工作日（按上面的规则）
  - 现在 ≥ 提醒时间
  - 今天还没生成总结
  - 今天还没提醒过
  - 没点过"今天不再提醒"
- 触发时：弹出主窗口到前台，同时发系统通知。
  - 标题：`该下班了`
  - 正文：`今天的工作总结可以生成了，已记录 N 条`
  - 开着"专注助手"时系统通知会被吞掉，所以弹出主窗口才是主要的提醒方式。
- **当天的补偿**（同 v1.0）：软件启动时，如果今天已经过了提醒时间、还没生成总结、也没提醒过，立即补弹一次。
- **漏生成的那天**【新】（界面稿 `5-生成总结与历史.html` ③）：
  - 软件启动时，往前找**最近一个"有记录但没生成总结"的日子**（不包括今天）。找到的话，今日页顶部显示黄色横幅：`上周五（10.16）有 4 条记录还没生成总结`，附两个按钮"现在生成"和"忽略"。
  - 只找最近一天，不会把几周前的都翻出来；点了"忽略"，那天就不再提示【我的判断】。
- 主窗口提供"今天不再提醒"按钮。

### 7.13 检查更新 【新】

- 仓库地址写死在程序里（`{owner}/{repo}`），等需求方建好 GitHub 仓库后确定。
- **检查方式**【我的判断】：不调用 GitHub API，因为 API 不登录每小时只能查 60 次，同一单位的人共用一个公网 IP，容易超限。改为请求 `https://github.com/{owner}/{repo}/releases/latest`，**不跟随跳转**，从返回的 `Location` 地址里取出 `/releases/tag/vX.Y.Z` 的标签号，和当前版本按 semver 比较。
- 检查时机：软件启动后 1 分钟检查一次，之后每 24 小时检查一次。设置页的"检查更新"按钮可以手动检查。
- 超时 8 秒。任何失败（断网、GitHub 打不开、还没有 Release）都不提示、不报错，只写日志。手动检查失败时才提示"连不上 GitHub，稍后再试"。
- 有新版本时：今日页顶部显示蓝色横幅：`有新版本 v1.2.0`，附两个按钮"去下载"和"稍后"。
  - 点"去下载"，用默认浏览器打开 `https://github.com/{owner}/{repo}/releases/tag/v1.2.0`
  - 点"稍后"，这个版本 3 天内不再提示；出了更新的版本会立即提示【我的判断】
- 截图、补充框、引导进行中时不弹任何更新提示。
- 同事下载新安装包后直接运行即可覆盖安装，数据都在 `%APPDATA%`，不受影响。安装器发现软件正在运行时会提示先关闭（Tauri 的 NSIS 安装器自带这个功能，验收时确认）。
- GitHub 在国内有时打不开或下载很慢。横幅上加一行小字："打不开？找{发布人}要安装包"，发布人的名字在构建时配置【我的判断】。

- 托盘图标常驻。双击打开主窗口。右键菜单：`截一张` / `打开主窗口` / `生成今日总结` / `退出`。
- 单实例：再次运行 exe 只会唤起已有的窗口，不开新进程。
- 点关闭按钮 = 最小化到托盘。第一次这样做时提示"已最小化到托盘，不会退出"。
- 热键注册失败（被别的软件占用）时，明确提示是哪个组合键失败了，并提供"去设置里换一个"的按钮。
- 图标：`.ico` 文件必须包含 16 / 20 / 24 / 32 / 48 / 256 六种尺寸，否则 125% 和 150% 缩放下托盘图标会糊【改】。

## 9. 异常与边界 【改】

| 情况 | 处理 |
|---|---|
| 没配 API Key 就截图 | 不报错。截图存好，条目进"待处理"，提示窗显示"先去设置页填接口信息，或手动写这一条" |
| AI 返回的不是合法 JSON | 按 7.4 的解析容错处理 |
| 网络断了 | 条目进"待处理"，网络恢复后不自动重试，提供手动重试 |
| 跨零点还在加班 | 条目按截图时间戳归到对应日期，不做跨天合并 |
| 当天 0 条就想生成 | 允许，只输出标题，并提示"今天还没记录" |
| 软件崩溃、断电 | 条目确认即落盘，并且是原子写入 |
| 多屏 + 不同缩放 | 每块屏一个框选窗口，按各自的缩放比例换算 |
| `data.json` 损坏 | 从最新一份能用的备份恢复，并告诉用户【新】 |
| 关了"允许 AI 新建分类"，AI 仍然返回了新标签 | 换成"其他"【新】 |
| 节假日数据没有当前年份 | 退回周一到周五规则，设置页提示更新软件【新】 |
| GitHub 打不开 | 自动检查时不提示；手动检查时提示连不上【新】 |
| 同事电脑上没有 WebView2 | 安装包里的补装程序联网安装；没网就提示"需要联网安装一个系统组件"【新】 |
| 热键被占用 | 提示，并引导去设置页换一个 |
| 截图时有程序禁止被截屏（部分银行、安全软件的窗口） | 截出来是黑块，属于正常现象，不处理【新】 |
